# Original-language source corpus

## Scope and rights

The `oshb` dataset is a separate source-study corpus from [Open Scriptures Hebrew Bible](https://github.com/openscriptures/morphhb/tree/3d15126fb1ef74867fc1434be1942e837932691f), pinned to commit `3d15126fb1ef74867fc1434be1942e837932691f` (2024-08-27). It is not a translated edition, not an alignment to any installed translation, and not an additional 66-book Bible. Source numbering is retained, including Joel's four chapters and Malachi's three. Navigation names and book order are application metadata.

The upstream [LICENSE.md](https://github.com/openscriptures/morphhb/blob/3d15126fb1ef74867fc1434be1942e837932691f/LICENSE.md) declares the underlying Westminster Leningrad Codex text Public Domain and supplies the OSHB annotations under [Creative Commons Attribution 4.0 International](https://creativecommons.org/licenses/by/4.0/). The upstream morphology-code HTML also explicitly declares CC BY 4.0. This import uses those primary upstream terms; it does not substitute an older secondary distributor's license.

Required upstream attribution, retained verbatim:

> Original work of the Open Scriptures Hebrew Bible available at https://github.com/openscriptures/morphhb

The complete LICENSE, project README, parsing README, original morphology-code HTML, and morphology key are under `data/original-language/oshb/notices/`. The HTML and XML documentation use `.txt` filenames and are preserved as data, not executed as HTML. The upstream book headers, including their contributor lists and source notices, are retained in every book bundle. Keep attribution, license links and these notices available when displaying, redistributing or exporting the source annotations. Identify this app's transformations: XML-to-JSON serialization, per-book bundling, navigation metadata and JSON extraction of the upstream grammar key/tables. No upstream endorsement or independent legal/editorial approval is asserted.

## Exact source and reproducibility

`source.json` pins the upstream commit and Git tree, archive URL/byte count/SHA-256, and all 44 selected files' byte counts, Git blob SHA-1 and SHA-256. Every file was checked against the exact upstream Git tree before admission. The 20,824,328-byte archive has SHA-256 `f979b5357fb18391928cd42ee1b95594db6e4f71d8da4e893c6c18f2688093a6`.

The importer uses only Python's standard library:

```sh
python scripts/import-oshb.py
python scripts/import-oshb.py --check
# An already downloaded exact archive can be supplied without network access:
python scripts/import-oshb.py --archive /path/outside/repository/pinned.tar.gz --check
node --test tests/oshb.test.mjs
```

Default downloads are cached under the operating system temporary directory, outside Git. The importer verifies the complete archive and every selected file before parsing. A changed archive, missing member, unknown reading element/type/attribute, unexpected namespace, duplicate source reference, DTD or entity declaration fails closed. It never downloads from a moving branch. Do not stage source caches or replace source pins merely to make a failed import pass.

`manifest.json` records per-book and per-chapter coverage, all generated payload hashes, observed and supported source markup, missing attributes, duplicate IDs and unexpanded morphology codes. `integrity.json` also hashes the manifest and the exact source pin, avoiding a self-referential manifest hash. Every generated output is deterministic. `--check` recreates all outputs in memory from the pinned XML and compares every generated byte.

## Reader API

All paths below are relative to `data/original-language/oshb/`. A consumer should fetch `manifest.json`, choose an OSHB book and chapter independently of the translated reader, then fetch the selected book's `path`. Do not derive source references from a translation's verse numbers. Book bundles are suitable for a bounded cache.

```ts
type SourceNode = {
  tag: 'w' | 'seg' | 'note' | 'catchWord' | 'rdg';
  attributes: Record<string, string>;
  content: Array<string | SourceNode>;
};
type SourceVerse = {
  osisId: string;                // exact source ID, e.g. Gen.1.1
  number: string;                // exact final source ID component
  content: Array<string | SourceNode>;
};
type SourceChapter = {
  schemaVersion: 1;
  sourceId: 'oshb';
  sourceRevision: string;
  osisId: string;
  book: string;                  // source OSIS book ID
  number: string;
  verses: SourceVerse[];
};
type SourceBook = {
  schemaVersion: 1;
  sourceId: 'oshb';
  sourceRevision: string;
  book: string;
  name: string;                  // application navigation name
  sourceTextAttributes: Record<string, string>;
  sourceHeader: object;          // complete source header tree
  chapters: SourceChapter[];
};
```

`manifest.books[]` contains `id`, `name`, `path`, `bytes`, `sha256`, `sourcePath`, `chapterCount`, `verseCount`, `counts`, and `chapters[]`. Each chapter entry supplies `osisId`, `number`, `verseNumbers`, `verseCount`, and `counts`. Use the inventory, not a presumed continuous English versification. Raw source attributes retain their original names and values: `id`, `lemma`, `morph`, `n`, `type` and `subType` where present. No IDs are synthesized. A word's displayed text is its own ordered string content plus nested segment content; it must not include neighboring note/readings. Strings include source whitespace. Render them as text; never interpret source notes as HTML.

## Reading alternatives and uncertainty

Verse-level `w` nodes form the source main text. A `w` with `type="x-ketiv"` is the written form. A following `note` with `type="variant"` retains a `catchWord` and a separate `rdg type="x-qere"`; the reading may contain more than one word. Display those relationships as the source supplies them. Do not flatten a qere into the main text, infer one-to-one alignment from adjacency, count both as a single chosen reading, or rewrite the ketiv's ID/morphology from the qere.

`note type="alternative"` contains accent alternatives, often as string-only `rdg type="x-accent"` without word IDs or morphology. `note type="exegesis"` and untyped notes may contain prose and string-only readings. Preserve the note/catchword boundaries. Segment nodes include maqqef, paseq, sof pasuq, paragraph markers, reversed nun and word-internal large/small/suspended letters. The 11 word-internal segments remain nested inside their original word.

Hebrew Unicode code points, combining-mark order, pointing, slashes and all word attributes are preserved. **Do not NFC-normalize this corpus:** the upstream README specifically warns against it. XML-defined character-reference and line-ending decoding is unavoidable parsing behavior; original source file bytes remain pinned. Between-verse/chapter XML indentation is omitted, but all mixed content within every verse and its notes is preserved. Source headers remain data.

There are no missing word ID, lemma or morphology attributes in this exact pin, but consumers must treat missing/empty values as unknown. A supplied code is an upstream annotation, not this application's independent linguistic verification. Upstream `x` placeholders do not justify claiming every grammatical feature is known. `morphology.json.codes` maps complete raw codes to the exact descriptions in the pinned `parsing/Oshm.xml`; descriptions retain original text. `tables` contains safe text from the upstream code tables. Eight codes used by nine word occurrences are absent from that exact key and are listed in `manifest.unexpandedMorphologyCodes`; keep their raw codes visible without guessing descriptions.

No Hebrew gloss lexicon, English word alignment, transliteration, pronunciation, audio, lemma sense definitions, syntax tree, theological claim or human editorial certification is added. Literal source lemma attributes can support source occurrence searches, but are not a license or evidence for an unrelated dictionary. The `n` cantillation annotation remains an uninterpreted source attribute here. `wlc/VerseMap.xml` is intentionally not imported or applied.
